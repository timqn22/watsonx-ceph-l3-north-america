# TrackerAssist Browser Extension (Simplified)

A Manifest V3 Chrome/Edge extension that shows related pull requests directly on Redmine issue pages.

## What it does

- **On an issue page** (`/issues/123`): injects a **Related pull requests** panel showing PRs that are semantically similar to the current issue, with similarity scores.
- Uses your existing `pr_issue_links.json` data generated by the PR monitoring system.

## Prerequisites

1. Make sure you have run the PR monitoring system to generate `pr_issue_links.json`:
   ```bash
   python3 pr_monitor_server.py  # Or use backport_prs.py to fetch historical PRs
   ```

2. Start the API server:
   ```bash
   python3 api_server.py
   ```
   The server will run on `http://localhost:8000` by default.

## Install (Chrome or Edge)

1. Open `chrome://extensions` (or `edge://extensions`).
2. Turn on **Developer mode** (top-right toggle).
3. Click **Load unpacked** and select this `extension/` folder.
4. Click the TrackerAssist toolbar icon to open the popup:
   - **Backend URL** — should be `http://localhost:8000` (default).
   - Click **Save** to confirm settings.
5. Visit any Redmine issue page on **tracker.ceph.com** — the "Related pull requests" panel will appear at the top.

## Configuration

The extension stores its configuration in Chrome's sync storage:
- **Backend URL**: The URL where your `api_server.py` is running (default: `http://localhost:8000`)

You can change these settings by clicking the extension icon in your browser toolbar.

## How it works

1. When you visit a Redmine issue page (e.g., `https://tracker.ceph.com/issues/78000`), the extension extracts the issue number.
2. It calls your backend API at `/issues/{issue_id}/related-prs`.
3. The backend reads from `issue_pr_links.json` to find PRs similar to that issue.
4. The extension displays these PRs in a panel at the top of the page with:
   - PR number and title
   - Similarity score (as a percentage)
   - PR state (open/closed)
   - Labels
   - Link to the PR on GitHub

## Customization

### Using a different Redmine host

To use with a Redmine instance other than tracker.ceph.com:

1. Edit `manifest.json`
2. Add your Redmine URL to both `host_permissions` and `content_scripts.matches`
3. Reload the extension in Chrome

### Changing the backend port

If your `api_server.py` runs on a different port:

1. Click the extension icon
2. Update the **Backend URL** field
3. Click **Save**

## Troubleshooting

**Panel shows "Backend offline"**
- Make sure `api_server.py` is running: `python3 api_server.py`
- Check that the Backend URL in the popup matches where your server is running
- The server enables CORS, so the extension can call it from Redmine pages

**No PRs shown**
- Make sure you have `issue_pr_links.json` in your project root
- Run `python3 generate_issue_pr_links.py` to create the file if it's missing
- The file is generated from your PR vector database

**Extension doesn't load**
- Make sure you selected the `extension/` folder (not a parent folder)
- Check the Chrome extensions page for any error messages
- Try reloading the extension

## Technical Notes

- The extension uses Manifest V3 (required for modern Chrome/Edge)
- Content scripts are scoped to `https://tracker.ceph.com/*`
- The backend uses permissive CORS headers for local development
- Chrome treats `localhost` as a secure origin, so HTTPS is not required for local testing
- Firefox support would require modifications (MV3 background worker differences)
